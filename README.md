# Курсовий проєкт: частотомір (Тема 2) на Verilog у системі з MicroBlaze

IP-модуль `freq_counter` рахує передні фронти зовнішнього сигналу `sig_in` за вимірювальне вікно, задане в тактах.
Керується програмою на C через AXI4-Lite. Vivado/Vitis 2026.1, кристал xc7z020clg400-1, такт 100 МГц. Плата не використовувалась, усе перевірено в симуляції.

## Архітектура
`програма на C -> MicroBlaze -> AXI4-Lite (SmartConnect) -> freq_counter (регістри + логіка)`; `sig_in` виведений назовні (Make External).

## Таблиця регістрів (база призначається Address Editor-ом; у збірці 0x0001_0000, 4 КБ)
| Зсув | Назва | Програма | Значення |
|---|---|---|---|
| 0x00 | WINDOW | пише/читає | тривалість вікна в тактах, [31:0] |
| 0x04 | CTRL | пише | запис 1 у [0] запускає вимірювання; читання дає 0; запис під час вимірювання ігнорується |
| 0x08 | COUNT | читає | кількість фронтів за останнє завершене вікно; не змінюється до наступного завершеного вимірювання |
| 0x0C | STATUS | читає | [0] = 1: вимірювання завершене, COUNT дійсний; під час вимірювання 0 |

Запис у COUNT/STATUS ігнорується (відповідь OKAY).

## Рішення, прийняті в проєкті
- `sig_in` асинхронний: 2-ступеневий синхронізатор, потім детектор фронту (`sync2 & ~sync3`). Широкий імпульс дає один фронт.
- Вікно = рівно WINDOW тактів, починається в такті запису в CTRL. STATUS скидається в тому ж такті.
- WINDOW = 0: вимірювання завершується одразу, COUNT = 0, STATUS = 1.
- Частоту рахує програма: f = COUNT * CLK_HZ / WINDOW.

## Очікувані результати (пораховані вручну до запуску) і пояснення
| Сценарій | Очікується | Як отримано |
|---|---|---|
| T1 період 100, вікно 1000 | COUNT = 10 | 1000 / 100 = 10, ціле число періодів, тому для будь-якої фази рівно 10 |
| T2 період 40, вікно 2000 | COUNT = 50 | 2000 / 40 = 50, так само рівно |
| T3 період 100, вікно 250 | COUNT = 2 або 3 | 250 / 100 = 2,5. Якщо перший фронт після початку вікна на такті p, фронти на p, p+100, p+200; третій потрапляє у вікно, лише коли p+200 < 250, тобто p < 50. Отже 3 при p < ~50, інакше 2. Результат залежить від фази сигналу відносно початку вікна (синхронізатор зсуває межу на 2-3 такти, але множина лишається {2, 3}) |
| T4 вікно 0 (граничний випадок) | STATUS = 1 одразу, COUNT = 0 | нульове вікно не містить тактів |
| T5 широкий імпульс: період 600, високий 400, вікно 1200 | COUNT = 2 | один фронт на імпульс; лічильник рівня дав би ~800 |
| T6 під час вимірювання (період 100, вікно 2000) | STATUS = 0, COUNT лишається 2 (з T5); повторний запис у CTRL ігнорується; підсумок 20 | 2000 / 100 = 20; тривалість ~2000 тактів, не довша |
| T7 після завершення | COUNT і STATUS стабільні | перевірка повторними читаннями |
| Система | COUNT = 10, f = 10 * 100 000 000 / 1000 = 1 000 000 Гц | вікно 1000 тактів, період 100 |

## Файли

## Як відтворити
```
vivado -mode batch -source scripts/package_ip.tcl      (крок 4: IP у ip_repo/)
vivado -mode batch -source scripts/build_system.tcl    (кроки 5, 7: Block Design, Implementation, звіти, XSA)
vitis  -s scripts/build_vitis.py                       (програма, .elf)
vivado -mode batch -source scripts/sim_system.tcl      (крок 6: системна симуляція з .elf)
```

## Проблеми, на які наткнувся
1. Запуск через регістр із затримкою на такт міг дати застаріле STATUS=1 одразу після запису в CTRL; тепер запуск і скидання STATUS відбуваються в такті запису.
2. Канали AW і W AXI4-Lite можуть приходити окремо; модуль запам'ятовує кожен і виконує запис, коли є обидва.
3. У Tcl хвилі не підставляли змінну в фігурних дужках; виправлено циклом із `foreach`.
